Guía de estilos, UI y front — MiCorreo

Fuente: extraído del proyecto de referencia Envios internacionales/Envio internacional CLAUDE (React + TypeScript + Vite), que a su vez replica el HTML/CSS de producción de MiCorreo. Documenta lo que se trajo a proto navegable: sólo chrome y design system, sin funcionalidad de negocio.

1. Arquitectura de tokens (3 capas)

Todo el look del producto vive en src/styles/tokens.css, organizado en tres capas que no deben saltearse:

CapaQué esQuién la usa
1. PrimitiveValores crudos (--grey-400: #ccc, --space-4: 1rem)Nadie directamente desde un componente
2. SemanticRol de uso (--text-muted, --surface-page)Puede usarse en componentes genéricos
3. ComponentMedida propia de un componente (--button-height, --field-radius)Es lo que consume cada .module.css

Regla dura: un componente nuevo consume tokens de capa 2 o 3, nunca literales ni tokens de capa 1 directo.

2. Marca y paleta

  • --correo-yellow: #ffce00 → color de marca
  • --correo-blue: #152663 → contraste de marca
  • --correo-grey-700: #49454f → texto secundario
  • --correo-near-black: #191919 → texto principal

Escala de grises de --grey-050 (fondo de página) a --grey-900 (texto principal). Estados: --red-* (error), --green-* (éxito), --blue-focus (foco de inputs, distinto del azul de marca).

3. Tipografía

Una sola familia, Gilroy, con pesos numéricos:

4. Espaciado, radios y sombras

  • Espaciado: escala de 4px (--space-1 = 4px … --space-12 = 48px).
  • Radios: --radius-xs (5px, inputs) hasta --radius-pill (32px, botones) y --radius-full (círculos).
  • Sombras: --shadow-row, --shadow-dropdown, --shadow-modal, --shadow-inset-active.
  • Capas (z-index): escala nombrada de --z-base a --z-demo-toolbar.

5. Chrome de la aplicación

Header

Barra superior fija, fondo amarillo, 60px de alto. Hamburguesa → logo → "Nuevo envío" y bloque de usuario (avatar + "Hola, {nombre}" + menú desplegable "Mi cuenta").

Sidebar

Riel de 61px (≥768px, sólo íconos) o cajón de 340px (offcanvas, con textos y submenús) según el mismo árbol de navegación.

Footer

Copyright + enlaces inertes (Preguntas frecuentes, Términos y condiciones, Botón de baja).

Layout de pantalla

PageContainer (narrow max 1200px / full a todo el ancho) + PageHeader (título, descripción, acciones) + ChatBubble flotante decorativo.

6. Primitivos de formulario

Comparten un sistema de label flotante (Field): sube al enfocar o tener valor, resuelto con :not(:placeholder-shown) — todo input necesita placeholder.

ComponenteRol
Input / TextareaCampo de texto con label flotante
SelectDesplegable — label siempre arriba
NumberInputInput numérico con spinners propios
Checkbox / RadioGroupMarcados en azul de marca (no amarillo, por contraste)
SwitchToggle accesible (role="switch")

7. Botones

VarianteUso
primaryFondo amarillo pleno, texto azul — acción principal
secondaryBlanco con borde amarillo — acción secundaria
tertiarySin fondo, sólo subrayado inferior amarillo
linkSin fondo ni borde, como un enlace

8. Feedback y overlays

  • Alert: banner inline, tonos danger/success/info/warning.
  • Badge: píldora de estado, mismos tonos + neutral.
  • Toast: cola de notificaciones, auto-cierre a los 4s.
  • Modal / ConfirmDialog: diálogos con portal, tamaños sm/md/lg/xl.

9. Datos y navegación secundaria

  • DataTable: filas separadas, sombra, radio por fila, encabezado sticky.
  • Pagination: paginador con elipsis.
  • EmptyState: bloque centrado para listas sin resultados.
  • Tabs: pestaña activa como bloque amarillo con esquinas redondeadas.
  • Stepper: 3 puntos conectados — visitado / activo / pendiente.

10. Assets

  • Logo: CorreoArgentino-MiCorreo.png — 28px de alto en el header, nunca estirar.
  • Fuentes: Gilroy Light/Regular/Medium/SemiBold/Bold/Heavy (.ttf).
  • Íconos del sidebar/header y chatbot.png (botón de chat flotante).

11. Qué NO forma parte de este chrome

Motor de roles/permisos, feature flags, escenarios de demo, mocks y módulos de dominio (envíos, cuenta, saldo). El usuario del header es un dato estático de ejemplo.

12. Cómo agregar un componente nuevo

  1. Carpeta en src/shared/ui/<Nombre>/ con .tsx + .module.css + index.ts.
  2. El CSS consume tokens semánticos/de componente — si falta uno, se agrega primero en tokens.css.
  3. Exportar desde src/shared/ui/index.ts.
  4. Si es de layout de página, va en src/shared/layout/.
